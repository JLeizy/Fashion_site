# AMFIBIA — маркетплейс брендовой одежды

Многостраничный интернет-магазин 15 модных домов (Balenciaga, Vetements, Gucci, Prada, Enfants Riches Déprimés, AVAVAV, Supreme,
Chrome Hearts, Louis Vuitton, Chanel, Maison Margiela, Givenchy, Versace, Alexander McQueen, Loro Piana) в эстетике высокой моды и готики.

**Стек:** HTML5 + CSS3 + JavaScript (ES-модули, без фреймворков), Node.js + Express 5, PostgreSQL (драйвер `pg`, чистый SQL),
GSAP + ScrollTrigger, Lenis, SplitType, OGL (WebGL), Chart.js. Подробный журнал разработки и план — в [PROGRESS.md](PROGRESS.md).

## Запуск

Нужны Node.js 20+ и PostgreSQL 15+ (если PostgreSQL не установлен — см. «Встроенный PostgreSQL» ниже).

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Создать `.env` из примера и указать данные своей БД (`PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`):
   ```bash
   cp .env.example .env
   ```
3. Базу создавать вручную не нужно: `npm run setup` сам создаст базу `PGDATABASE`, если её нет
   (у пользователя `PGUSER` должно быть право `CREATEDB`; у стандартного `postgres` оно есть).
4. Схема + наполнение + SVG-заглушки картинок:
   ```bash
   npm run setup
   ```
5. Запуск → http://localhost:3000
   ```bash
   npm start
   ```

**Встроенный PostgreSQL** (если своего нет): в `.env` поставить `USE_EMBEDDED_PG=true` и `PGPORT=5433` — сервер сам поднимет
PostgreSQL из npm-пакета `embedded-postgres` (данные в папке `.pgdata/`).

Повторный `npm run setup` пересоздаёт базу с нуля (все тестовые данные вернутся в исходное состояние).

## Где что хранится

- `db/schema.sql` — все таблицы, индексы, триггеры, представления (с `COMMENT ON`); `db/seed.js` — наполнение.
- `db/pool.js` — единственная точка доступа к БД (`query`, `withTransaction`).
- `server/routes/api/*.js` — REST API; над каждым маршрутом комментарий: что делает, какие таблицы читает/меняет, какая роль.
- `server/services/orderService.js` — оформление заказа и смена статусов (транзакции, резерв и списание остатков).
- `views/*.html` — страницы, `public/css`, `public/js` — стили и клиентская логика, `public/i18n/ru.json`, `en.json` — тексты интерфейса.
- `public/images/brands/<бренд>/products/<sku>-1.svg` — SVG-заглушки фото (генерирует `npm run placeholders`).

## Фотографии

> Фотографии принадлежат их правообладателям; проект предназначен только для локальной демонстрации и не публикуется.

- Реальное фото лежит рядом с заглушкой под тем же именем, но в формате `.webp`: `/images/brands/<бренд>/products/<sku>-1.webp`,
  `-2.webp` (второй ракурс для смены при наведении), `directors/<n>.webp`, `history/<n>.webp`, `collections/<имя>.webp`, `hero.webp`,
  `/images/banners/<бренд>.webp`. При `npm run db:seed` в БД пишется путь к `.webp`, если файл есть (`db/imagePath.js`), иначе к `.svg`.
  Если фото не загрузится, страница сама подставит SVG-заглушку.
- **Подобрать источники автоматически:** `npm run images:collect -- --brand balenciaga` — товары сопоставляются с вещами бренда на SSENSE (категория, модель, цвет; нужен Playwright), обложки коллекций, hero, баннер и иллюстрации истории — образы показов Vogue Runway, портреты — Википедия; план по брендам — `db/content/image-plan.js`. Результат дописывается в `db/content/image-sources.json`.
- **Скачать / перекачать фото:** заполнить `db/content/image-sources.json` (массив
  `{ "target": "/images/brands/gucci/products/GUC-LOF-0001-1.webp", "kind": "product", "page": "страница-источник", "url": "прямая ссылка на картинку", "note": "примечание" }`;
  `kind` — `product | collection | history | director | hero | banner`; без `url` страница откроется в Chromium и возьмётся `og:image`), затем:
  ```bash
  npm run images
  ```
  (`-- --brand gucci` — только один бренд, `-- --force` — перекачать, `-- --from-manifest` — перекачать всё по `db/content/images-manifest.json`),
  после чего `npm run db:seed && npm run placeholders`. Скрипт `scripts/fetch-images.js` идемпотентен, делает паузы и повторы, через `sharp`
  переводит в webp (≈80 %; hero/баннеры до 1600 px, товары/коллекции/история до 900 px, портреты до 600 px, товары ≤ 100 КБ)
  и записывает в манифест страницу-источник, URL, дату и примечание.
- **Заменить своими:** положить свой файл `.webp` с тем же именем (или `.jpg` и сконвертировать любым редактором в `.webp`)
  и выполнить `npm run db:seed && npm run placeholders`.


## Запуск на Windows

Проверено для Windows 10/11 и PowerShell. Нужен Node.js 20+ (установщик с nodejs.org, галочка «Tools for native modules» не обязательна).

**Вариант А — без установки PostgreSQL (встроенный сервер из npm-пакета).**

1. В папке проекта:
   ```powershell
   npm install
   ```
2. npm 11 по умолчанию не запускает install-скрипты пакетов. Разрешить их для трёх пакетов с нативными частями и пересобрать:
   ```powershell
   npm install-scripts approve @embedded-postgres/windows-x64 bcrypt sharp
   ```
   ```powershell
   npm rebuild
   ```
   (на npm 10 и старше эти два шага не нужны — скрипты выполняются при `npm install`).
3. Скопировать пример окружения:
   ```powershell
   Copy-Item .env.example .env
   ```
   В примере уже стоят `USE_EMBEDDED_PG=true` и `PGPORT=5433` (порт 5433 — чтобы не конфликтовать с установленным PostgreSQL,
   если он есть), менять ничего не нужно. Важно: повторный `Copy-Item` перезапишет ваши правки в `.env`.
4. Схема, наполнение и заглушки (встроенный PostgreSQL поднимется сам, данные — в папке `.pgdata`):
   ```powershell
   npm run setup
   ```
5. Запуск → http://localhost:3000
   ```powershell
   npm start
   ```

**Вариант Б — свой PostgreSQL 15+ (установщик EnterpriseDB).** В `.env` поставить `USE_EMBEDDED_PG=false`, указать `PGPORT=5432`,
`PGUSER=postgres` и пароль, заданный при установке; затем `npm run setup` и `npm start`. Расширение `pg_trgm` входит в стандартную
поставку PostgreSQL для Windows.

Типичные проблемы:
- `Cannot find module ... sharp` или ошибка `bcrypt` — не выполнены шаги 2 (approve + rebuild).
- Порт 5433 занят — указать в `PGPORT` другой свободный порт и снова `npm run setup`.
- Кириллица в JSON при проверке API через `curl` из Git Bash портится — отправлять тело из UTF-8 файла (`--data-binary @file.json`).
- Чтобы начать с чистой базы, достаточно повторить `npm run setup` (со встроенным PostgreSQL можно также удалить папку `.pgdata`).

### Состояние фото и каталога (ноябрь 2026)

**Каталог — только реальные вещи.** Каждый товар сайта — конкретная вещь из магазина-источника: название, цвет, категория,
материал, цена и фото взяты из **одной** карточки, поэтому фото всегда совпадает с товаром. Цвета одной модели — отдельные
товары с общим `model_code` и **своими** фото: переключатель цвета на странице товара показывает снимок именно этого цвета.

| Бренды | Источник товаров |
|---|---|
| Chanel, Prada | официальные сайты марок (страницы товаров, разметка schema.org/Product) |
| Chrome Hearts | официальный онлайн-магазин (ароматы, хрусталь Baccarat, бельё, носки, шарф, тапочки) + украшения, очки и сумки с Fashionphile |
| Gucci, Louis Vuitton, Loro Piana | Fashionphile — подлинные вещи с экспертизой (ресейл): продаются продавцами-ресейлерами, по одному экземпляру |
| Enfants Riches Déprimés | официальный сайт марки |
| Balenciaga, Givenchy, Maison Margiela, Versace, Vetements, Alexander McQueen, AVAVAV, Supreme | ранее скачанные фото конкретных вещей из SSENSE и официального магазина Supreme: товар получил название и цвет той вещи, что на фото |

- Сборка: `npm run catalog -- --brand <бренд>` (или `--all`) → `db/content/catalog/<бренд>.json` и фото
  `public/images/brands/<бренд>/products/<ключ вещи>-1.webp`, `-2.webp` (второй ракурс, если он есть у магазина).
  Правила распознавания категории, цвета и материала — `scripts/lib/catalog-rules.js`.
- Русские названия строятся как в русских люкс-магазинах: тип вещи по-русски + модель латиницей («Кроссовки Triple S»);
  свои переводы можно задать в `db/content/catalog-ru.json` (`"название EN": "название RU"`).
- Вещи с перечёркнутой свастикой (принт Vetements Antihate) в каталог и на фото не попадают.

**Лукбуки и обложки коллекций** — `npm run images:editorial -- --brand <бренд>` (или `--all`):
- каждая коллекция = настоящий показ того же сезона на Vogue Runway; лукбук — первые 10 выходов показа по порядку
  (таблица `collection_looks`), обложка — первый выход; коллекции брендов приведены к реальным показам;
- разделы истории иллюстрируются выходами показов **из лет этого раздела**; если показов той эпохи нет — остаётся фото из
  Википедии или раздел идёт без иллюстрации (без случайных кадров из других лет);
- ни один кадр не повторяется в пределах бренда; показ Vetements весна–лето 2026 (футболки с перечёркнутой свастикой)
  исключён целиком (`excludeShows` в `db/content/image-plan.js`).

Источник каждого снимка — `db/content/image-sources.json`. Портреты директоров — Википедия; если портрета нет, стоит выход
показа из лет работы директора с пометкой; ручные правки — `db/content/image-overrides.json`.

## Как заменить фотографии (кратко)

1. Найти имя файла: открыть товар на сайте → в DevTools у картинки виден путь вида `/images/brands/gucci/products/fp-10689532559663-1.webp`.
   Второй ракурс — тот же ключ с `-2`.
2. Положить свой файл **в формате `.webp`** с этим именем в `public/images/brands/<бренд>/products/` (для директоров — `directors/`,
   для истории — `history/<номер раздела>.webp`, для коллекций — `collections/`, обложка бренда — `hero.webp`, баннер — `public/images/banners/<бренд>.webp`).
   JPG/PNG можно перевести в webp любым редактором (качество ≈80 %, ширина до 900 px для товаров, до 1600 px для hero и баннеров).
3. Выполнить:
   ```bash
   npm run db:seed && npm run placeholders
   ```
   Сид запишет в базу путь к `.webp`, а `placeholders` не тронет файлы, у которых уже есть реальное фото.
4. Чтобы вернуть заглушку — удалить `.webp` и повторить шаг 3. Чтобы перекачать фото из источника — `npm run images -- --brand <бренд> --force`.
5. Логотипы на фотографиях допустимы (это реальные вещи); вёрстка сама логотипы брендов не рисует.

модератору и владельцу (`pageCheckRole('moderator')`), остальным показывается 403; кабинеты сотрудников — разделы `/account`,

## Финальная проверка (этап 31)

Проверено автоматическим скриптом в Chromium (Playwright) на 15 страницах (главная, каталог, бренд, история, оглавление историй,
товар, корзина, сравнение, вход, доставка, контакты, о нас, размеры, отслеживание, 404) в трёх темах (`amfibia`, `light`, `dark`),
на десктопе 1440×900 и на iPhone 13:

- консоль браузера — без ошибок; горизонтальной прокрутки нет;
- контраст текста по WCAG AA (4.5:1, крупный текст 3:1) на однотонном фоне — без нарушений; исправлено: номера и названия брендов
  в указателе слайдов на главной (было 4.0:1) и шапка в светлой теме поверх тёмной обложки (главная и страница бренда) — теперь светлая
  до прокрутки (на страницах истории обложка в светлой теме высветлена, шапка там остаётся тёмной); текст поверх фотографий проверялся по скриншотам;
- фокус с клавиатуры: на первых 25 остановках Tab у каждого элемента видна рамка фокуса во всех темах;
- Esc закрывает поиск, мини-корзину, мега-меню и мобильное меню (модальные окна — через общий `ui/modal.js`).

Повторный прогон после завершения всех 15 историй (ноябрь 2026): те же 15 страниц в трёх темах на десктопе и телефоне — консоль
без ошибок, фокус и Esc работают; все 15 страниц `/history/<slug>` отвечают 200 без ошибок консоли. Скрипт отмечает «нарушения
контраста» в светлой теме на главной и странице бренда — это текст поверх фотографии обложки, где скрипт не может определить фон;
по скриншотам шапка и подписи читаются (светлый текст на затемнённой обложке).

Edge построен на Chromium, поэтому результаты Chromium к нему применимы. Firefox в окружении разработки недоступен — его стоит
проверить вручную: открыть те же страницы, переключить три темы, пройти Tab по шапке и нажать Esc в поиске и корзине.
